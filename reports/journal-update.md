# บันทึกหลายหมวดและเวลาแบบยืดหยุ่น

เปลี่ยน workflow ตามคำขอผู้ใช้วันที่ 12 ตุลาคม 2026: พิมพ์ครั้งเดียว แยกหลายหมวด ใช้วันที่พิมพ์เป็นค่าเริ่มต้น รับช่วงเช้า/เที่ยง/บ่าย/เย็น/กลางคืน แล้วเติมเวลาเป๊ะทีหลังได้

เส้นทางหลักใช้ตัวแยกข้อความไทยและโปรแกรมสำหรับเวลา/วันที่/หน่วย ไม่บังคับโหลดโมเดลกับข้อความที่อ่านได้ชัดเจน ส่วนข้อความที่ไม่แน่ใจหมวดส่งให้ Typhoon ในเครื่องเสนอเฉพาะหมวด โดยต้องคืน source span เดิมเท่านั้น โมเดลไม่มีหน้าที่เติมค่าตรวจ คิดระยะเวลา หรือเปลี่ยนยา ข้อความที่ยังอ่านไม่ได้แสดงในหน้าตรวจให้เลือกหมวดเองหรือเลือกไม่เก็บอย่างชัดเจน

เวลาที่ทราบเพียงช่วงวันเก็บเป็น enum พร้อมข้อความต้นฉบับ ไม่แปลง “ตอนบ่าย” เป็นชั่วโมงสมมติ วันเริ่มพิมพ์เก็บเป็น timestamp และคำนวณวันด้วย Asia/Bangkok จึงไม่ขึ้นกับ timezone ของ Mac และไม่เปลี่ยนวันเมื่อยืนยันหลังเที่ยงคืน Explicit relative dates และวันที่ ISO / dd/mm/yyyy (รวมปี พ.ศ.) มี provenance แยกจากวันที่เริ่มต้น หากเป็นหัวข้อช่วงเวลาแยกบรรทัด เก็บข้อความหัวข้อนั้นใน context_text ให้ตรวจได้

เพิ่ม `journal` ใน record schema ข้อมูลที่ไม่ครบเก็บได้ในฐานะข้อความที่ผู้ใช้ยืนยัน โดยสถานะความครบยังเป็น unknown; กฎตัวเลข/หน่วย/ช่วงเวลาที่ผิดยังปฏิเสธ บันทึกบางช่องได้โดยไม่แต่งช่องที่เหลือ Summary ข้ามกิจกรรม/การนอนที่ขาดเวลาเริ่ม–จบ และข้ามค่าตรวจที่ยังเทียบกันไม่ได้ ไม่เปลี่ยน missing เป็นศูนย์

การยืนยัน batch เป็น SQLite transaction เดียว มี retry digest และ rollback ทุกแถวเมื่อพบปัญหา การเติมเวลาใช้ append-only version เดิมก่อนแก้ยังอยู่ Export/delete และ owner scoping ใช้ชุดเดียวกับระบบเดิม Supabase interface เก็บ `_journal`/`_text` ใน JSON payload และ migration อนุญาต unknown เฉพาะบันทึกข้อความในตารางกิจวัตร; ยังไม่ได้ execute/test RLS บน PostgreSQL จริง

ผลทดสอบ:

- pytest ตรวจ parser, 7 หมวด, วันที่ไทย/เที่ยงคืน, ช่วงเวลา, การนอนข้ามวัน, negation/intention, ตัวเลขคล้ายเวลา, rollback/retry, API batch และเติมเวลาเป็นเวอร์ชันใหม่
- jsdom โหลด HTML และ JavaScript ของแอปจริง ทดสอบพิมพ์หลายหมวด ตรวจ ยืนยัน เปิดประวัติเติมเวลา และป้องกันใช้ผลเก่าหลังข้อความเปลี่ยน ไม่มีข้อมูลทดสอบลงฐานข้อมูลเดโม
- [journal-software-check.json](journal-software-check.json) เก็บผลชุดข้อความไทย 13 กรณีและ actual Typhoon smoke สำหรับสองข้อความที่ตัวแยกหมวดยังอ่านไม่ออก ผลดิบ/เวลา/MLX peak เป็นค่าที่รันจริง
- รอบแรกพบการแยก “รู้สึกเหนื่อยและเครียด” เป็นสองรายการ แก้ให้ความรู้สึกที่ต่อด้วย “และ” อยู่รายการเดียว เก็บรายงานรอบแรกแยกไว้ ไม่ซ่อนข้อผิดพลาด

นี่เป็นการเพิ่มความถูกต้องและความสะดวกของ workflow ตาม software cases ยังไม่มี benchmark ข้อความจากผู้ใช้จริงที่มีผู้ตรวจหลายคน จึงไม่อ้าง “แม่นยำที่สุด” หรือเปอร์เซ็นต์ความแม่นยำทางคลินิก ไม่ฝึกเพิ่มด้วยข้อความที่แต่งเพื่อทดสอบ ต้องใช้ข้อมูลไทยจริงที่มีสิทธิและ labels จากมนุษย์ก่อนประเมินความสามารถทั่วไป
