# การเลือกแหล่งข้อมูลอัตโนมัติ — เวอร์ชัน 0.5.0

แก้กรณี “เป็นเบาหวานจะอ้วนใช่ไหม” ซึ่งเดิมค้นไม่พบเพราะไม่มี alias “อ้วน” และไม่มีหลักฐานเฉพาะหัวข้อนี้ เพิ่มคำใกล้เคียงและสรุปภาษาไทยจาก NIDDK เรื่องปัจจัยเสี่ยง อาการ น้ำหนักลด และการวินิจฉัย โมเดลจริงตอบ HTTP 200 / answered_by_model ใช้ generation 9.84 วินาที peak memory 3.05 GB รายงาน `chat-model-weight-smoke.json`

หน้าแชตเลือกแหล่งข้อมูลอัตโนมัติ ไม่มี dropdown: คำถามบันทึก/ค่าที่เจ้าของยืนยันอ่านฐานข้อมูลของเซสชัน; คำถามความรู้สุขภาพใช้หลักฐานและโมเดล; คำถามนอกสุขภาพถูกปฏิเสธ ประวัติคำถามใช้ช่วยตีความคำถามต่อ แต่คำถามนอกเรื่องใหม่ไม่สืบทอดสิทธิสุขภาพ ค่า scope รุ่นเก่าใน API ยังรับได้เพื่อความเข้ากันได้ แต่ไม่ข้ามนโยบายอัตโนมัติ

เมื่อข้อมูลในเครื่องไม่พอ ค้น MedlinePlus Web Service ของ U.S. National Library of Medicine ตาม [เอกสารทางการ](https://medlineplus.gov/about/developers/webservices/) ไม่ต้องมี API key ส่งเฉพาะชื่อหัวข้อภาษาอังกฤษจาก allowlist ไม่ส่งข้อความผู้ใช้ ประวัติแชต บันทึก หรือคุกกี้ส่วนตัว ค้นเฉพาะ fixed HTTPS endpoint ไม่ตาม redirect รับเฉพาะ URL medlineplus.gov และเก็บผลสาธารณะใน RAM 1 ชั่วโมง ถ้าเครือข่ายใช้ไม่ได้จะแจ้งตามจริง ไม่มีการสร้างหลักฐานทดแทน

ลองเชื่อมต่อจริงด้วยหัวข้อ headache พบ MedlinePlus FullSummary และตรวจว่าคำถามหุ้นคืน out_of_scope โดยไม่มีคำตอบจากโมเดล (`chat-off-topic-smoke.json`) ระหว่าง smoke test ออนไลน์พบข้อผิดพลาดการแปลศัพท์ของโมเดล 4B จึงเก็บผลก่อนแก้ไว้ในรายงาน before-terminology / before-focused-prompt แล้วจำกัดหลักฐานให้ตรงหัวข้อที่สุดและกำกับศัพท์ คำตอบยังต้องตรวจสอบกับแหล่งต้นฉบับ ไม่ใช่ระบบที่ผ่านการประเมินทางคลินิก

ผลตรวจซอฟต์แวร์: pytest 75 passed; Node/jsdom 8 passed ครอบคลุม routing, follow-up, scope bypass, owner isolation, ไม่เขียนข้อมูล, ค้นออนไลน์ด้วยหัวข้อที่อนุญาต, กรอง URL, cache, network failure และ 404 retry ไม่ใช่คะแนนความแม่นยำทางการแพทย์

# หน้าแชตสุขภาพ — เวอร์ชัน 0.4.0

เพิ่มเมนู “แชตสุขภาพ” พร้อมข้อความต่อเนื่อง, คำถามตัวอย่าง, เลือกขอบเขตข้อมูล, Enter/Shift+Enter, สถานะกำลังตอบ, อ้างอิงบันทึก/เอกสาร, เริ่มบทสนทนาใหม่และยกเลิกคำตอบที่ยังรออยู่ ใช้ HTML/CSS/JavaScript ของเดโมเดิม

`POST /api/chat` อ่าน owner จากเซสชันที่ผ่าน CSRF แล้วเท่านั้น ไม่รับ owner จากข้อความและไม่เขียน records/plans/audit ประวัติแชตเก็บในหน่วยความจำหน้าเว็บ ไม่เพิ่มเข้า training หรือฐานข้อมูล บันทึกที่อ้างอิงเป็น current versions เท่านั้น

คำถามข้อมูลส่วนตัวค้นรายการที่ยืนยัน แยกวันที่ตาม Asia/Bangkok และเก็บช่วงเวลาที่ผู้ใช้ระบุ ระยะเวลากิจกรรม/นอนใช้ calculator; รายการที่ขาดเวลาไม่กลายเป็นศูนย์และมีคำอธิบาย สามารถถามต่อ เช่น “แล้วเมื่อวานล่ะ” โดยใช้หมวดจากคำถามก่อนหน้าแล้วค้นข้อมูลจริงใหม่ คำว่า “ล่าสุด” แสดงรายการที่บันทึกล่าสุดพร้อมวันเวลา ไม่ตีความเป็นผลตรวจล่าสุดทางคลินิก

ความรู้สุขภาพเรียกโมเดล Typhoon 2.5 Qwen3 4B แบบ 4-bit ผ่าน local MLX worker จริง โดยใช้หลักฐาน NIDDK ที่ค้นได้และสรุปสาระภาษาไทยที่ระบุ `editorial_summary` ชัดเจน ไม่ใช้ pilot LoRA กับคำตอบสุขภาพ ไม่ส่งบันทึกเจ้าของเซสชันเข้าโมเดลความรู้ทั่วไป คำถามอาหาร เช่น “ฉันเป็นเบาหวานฉันจะกินอะไร” ไม่ถูกตีความเป็นค้นประวัติอาหารอีกต่อไป คำถามนอก corpus คืน unknown การปรับยา/ขนาดยา/วินิจฉัยยังอยู่นอกขอบเขต

เพิ่มหลักฐานเรื่อง remission จาก [NIDDK](https://www.niddk.nih.gov/health-information/professionals/diabetes-discoveries-practice/achieving-type-2-diabetes-remission-through-weight-loss) และสรุปหัวข้ออาหารจาก [Healthy Living with Diabetes](https://www.niddk.nih.gov/health-information/diabetes/overview/healthy-living-with-diabetes) สรุปภาษาไทยเป็นงานเรียบเรียงโดยผู้พัฒนา ไม่ใช่คำแปลที่ผ่านการรับรองทางคลินิก ไม่ใช้เกณฑ์ remission เชิงตัวเลขจากบทความเก่า

ตรวจ API ของเซิร์ฟเวอร์จริง: `/api/chat` ตอบ HTTP 200 และ schema เป็นเวอร์ชัน 0.4.0 ไม่พบ 404 ในพอร์ต 8765 ที่ตรวจ จึงยังระบุสาเหตุ 404 ก่อนหน้าของผู้ใช้ไม่ได้ เพิ่มข้อความช่วยเปิดพอร์ตที่ถูกต้องและเริ่มเซิร์ฟเวอร์ใหม่เมื่อพบ 404 พร้อมเก็บคำถามให้ลองซ้ำ

ทดสอบโมเดลจริงด้วยสองคำถามตัวอย่างที่ไม่มีข้อมูลส่วนตัว: เรื่องอาหารและเรื่อง remission ได้ `answered_by_model` ทั้งคู่ ในคำตอบอาหารรอบแรกพบการแปลศัพท์ผิด และอีกรอบพบคำอธิบายไขมันผิด จึงปรับให้ใช้สรุปหลักฐานภาษาไทยและศัพท์กำกับ รายงานก่อนแก้เก็บไว้ใน `chat-model-food-smoke-before-thai-grounding.json` เพื่อไม่ปิดบังข้อผิดพลาด ผลอาหารล่าสุดใน `chat-model-food-smoke.json` ใช้ศัพท์และสัดส่วนจานถูกต้อง: load 1.28 วินาที, generation 7.62 วินาที, peak memory 3.07 GB ส่วนคำถาม remission ทดสอบจริงก่อนเปลี่ยนหลักฐานเป็นภาษาไทย: load 1.38 วินาที, generation 12.00 วินาที, peak 2.91 GB; ยังไม่ได้ทดสอบคำถามนี้ซ้ำหลังเปลี่ยนหลักฐาน ผลเหล่านี้เป็น smoke test ไม่ใช่คะแนนความถูกต้องทางคลินิก

ตัวเรียกโมเดลจำกัดงานพร้อมกัน มี timeout และคืนข้อความที่ลองแก้ไขได้เมื่อโหลดล้มเหลว โดยไม่เปิดเผย prompt/stderr ใช้ `scripts/run_demo.py --reload` ระหว่างพัฒนาเพื่อโหลดการเปลี่ยนแปลงใน app/services อัตโนมัติ

ผลตรวจ: pytest 52 passed; Node 8 passed รวม jsdom ของหน้าแชต ทดสอบ owner isolation, read-only, CSRF, follow-up, missing duration, exact citation text, ไม่ตีความ HTML จากข้อความ, ประวัติสนทนา และ reset ระหว่างรอคำตอบ ไม่มี software fixture ในฐานข้อมูลเดโม ไม่อ้างว่าผ่านการตรวจ visual browser หรือความเหมาะสมทางคลินิก
